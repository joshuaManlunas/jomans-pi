T3 Meshed Agents

A quick guide to standing up a team in T3 Code.

Your current thread is the orchestrator. Add an optional advisory Oracle and N workers, each in its own delegate (child) thread under the orchestrator, spawned with delegate_task. Every member can message every other member directly through t3_thread_send.

T3 Code only, not Herdr. The team reads its role prompts from this skill directory by default.

Choose the team

Invocation flags; worker count excludes you and the Oracle.
FlagDefaultUse
--workers N4Positive worker count.
--worker-model inst:model[,inst:model...]codex:gpt-6.1-solOne selection for all workers, or exactly N selections in worker order.
--oracle inst:modelcodex:gpt-6-astraChoose the Oracle independently.
--no-oracleUnsetOmit the Oracle; mutually exclusive with --oracle.
--prompts-dir DIRThis skill directoryExisting orchestrator.md, workers.md, and, with Oracle, oracle.md.

Find exact provider and model IDs with the T3 tool orchestrator_capabilities. A selection is providerInstanceId:modelId, split at the first colon. Examples require those providers/models to be available; the agent checks them before launch.

Sample usages

Use the / line in Claude Code or the $ line in Codex. Enter one line as an agent prompt in T3 Code, not as a shell command.

Default: four Codex workers and a Codex Oracle

/t3-meshed-agents
$t3-meshed-agents

Two mixed workers and a Codex Oracle

/t3-meshed-agents --workers 2 --worker-model codex:gpt-6.1-sol,claudeAgent:claude-sonnet-5-5 --oracle codex:gpt-6-astra
$t3-meshed-agents --workers 2 --worker-model codex:gpt-6.1-sol,claudeAgent:claude-sonnet-5-5 --oracle codex:gpt-6-astra

Three workers without an Oracle

/t3-meshed-agents --workers 3 --no-oracle
$t3-meshed-agents --workers 3 --no-oracle

All-Claude workers and Oracle

/t3-meshed-agents --workers 3 --worker-model claudeAgent:claude-sonnet-5-5 --oracle claudeAgent:claude-opus-5-5
$t3-meshed-agents --workers 3 --worker-model claudeAgent:claude-sonnet-5-5 --oracle claudeAgent:claude-opus-5-5

Maximum: twenty workers, no Oracle

/t3-meshed-agents --workers 20 --no-oracle
$t3-meshed-agents --workers 20 --no-oracle

At most 20 new threads, also limited by features.maxBatchThreads. With an Oracle, the maximum is 19 workers. Your current orchestrator thread is additional and keeps its model, including in the all-Claude example.

What standup looks like

Plan → create threads → BOOT_ACK → pairs → matrix → READY → charter. Members load their roles, prove direct PING/ACK communication for every pair, then acknowledge READY. Work starts only after a later assignment. With n total members, verification covers n(n−1)/2 pairs.

The helper lives beside SKILL.md. With Node.js ≥18, set T3_MESH_SKILL_DIR to this skill directory; run data lives under T3_MESH_ROOT or /tmp. These are helper commands for the agent, not replacements for the skill:

plan — write the plan and print one delegate_task payload per member.
node "$T3_MESH_SKILL_DIR/t3-mesh.mjs" plan
bootstrap — validate the saved delegate_task responses and generate roles, roster, and messages.
node "$T3_MESH_SKILL_DIR/t3-mesh.mjs" bootstrap --run "$T3_MESH_RUN" --orchestrator-thread "$T3_ORCHESTRATOR_THREAD"
matrix — verify recorded pair reports and write the pair matrix.
node "$T3_MESH_SKILL_DIR/t3-mesh.mjs" matrix --run "$T3_MESH_RUN"
selftest — test the helper without launching threads.
node "$T3_MESH_SKILL_DIR/t3-mesh.mjs" selftest

The agent retains run/directory values from plan, its thread ID from orchestrator_capabilities.parentThreadId, and saves each delegate_task response to the save path in its payload (delegate-<name>.json).

After READY

Assign work to the squad

Use the ready squad to implement the requested change. Assign disjoint files, give each worker acceptance criteria and checks, then review and integrate their results.

Consult the Oracle

Ask the Oracle to critique this implementation plan before we edit. Send the task context and constraints, wait for its result, then decide how to proceed.

Raise a worker's effort

Ask Leia to raise her own reasoning effort to the highest supported level using t3_thread_configure and the option IDs from orchestrator_capabilities. Keep her provider and model unchanged.

Keep the orchestrator role

After READY, the orchestrator saves a squad charter to its persistent memory. The charter records the mission, the worker model and the rules. When the conversation is compacted or has been idle, the orchestrator reads the charter and lists the live workers before doing anything else. That way it keeps delegating instead of doing the work itself. Once a worker's output is merged, the orchestrator archives that worker's thread.

Roles are loaded conversationally, not injected as system prompts. Members share your project, branch, worktree, and checkout, so give them separate file ownership. Effort changes are provider-specific and made by the member itself.
